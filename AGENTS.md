# Recruitment ERP

Next.js App Router application using React 19, TypeScript, and Tailwind CSS v4.

## Development

Run `pnpm dev` to start the development server, `pnpm build` to create a production build, and `pnpm start` to serve it.

For browser and closed-browser push alerts, apply `supabase/migrations/20261031123905_browser_push_notifications.sql`, `supabase/migrations/20261031131429_notification_push_cron_scheduler.sql`, and `supabase/migrations/20261031140816_workspace_notification_events.sql`. The last migration adds permission-scoped event notifications for candidates, tasks, approvals, finance, HR, medical examinations, and inbound WhatsApp messages; legacy leave, requisition, and reminder notifications remain supported. Set `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, and `NOTIFICATION_DISPATCH_SECRET` only in the app server environment. In Supabase Vault, create secrets named `notification_app_base_url` (the HTTPS app origin) and `notification_dispatch_secret` (the same value as the app's `NOTIFICATION_DISPATCH_SECRET`). Supabase Cron then calls `/api/notifications/push/dispatch` every minute. Users opt in from the notification center; push subscriptions are scoped to the signed-in user and alerts are permission-filtered.

For staff self-service profile names, phone numbers, and profile photos, apply `supabase/migrations/20261104093919_user_profile_photos.sql`. The migration adds `profiles.avatar_url` and a private Storage bucket; profile photos are served through the authenticated `/api/workspace/my-profile` route and are not public URLs.

For staff line-manager assignments and employee employment summaries, apply `supabase/migrations/20261113045438_staff_line_managers.sql`. Staff invitations let administrators choose Staff or Member; email invitations require the invitee's phone number. When inviting an existing active, unlinked staff member, search by name and select the roster record to autofill its saved details and link the account instead of creating a duplicate. New Staff invitations create a linked roster record with branch, line manager, and pay details. The Agents page lists company users assigned the Recruitment Agent role; invitations are managed from Users & Roles. The Chairman can edit the Main Branch and change a user's Staff/Member type from Users & Roles; changing Staff to Member retains the staff history and marks its roster record inactive. The Chairman, General Manager, and Supervisor can filter visible users by branch. Employees can view their own position, line manager, branch, monthly salary, and weekly transport allowance in Human Resource.

## Project Structure

- `src/app/page.tsx` - App Router page
- `src/app/layout.tsx` - Root HTML layout, metadata, and global CSS import
- `src/App.tsx` - Client-side recruitment dashboard and navigation
- `src/components/` - Dashboard modules
- `src/index.css` - Global styles and Tailwind CSS v4 theme
- `package.json` - Dependencies and scripts

## Dependencies

- Runtime: Next.js 16, React 19, and React DOM 19
- Styling: Tailwind CSS v4 through `@tailwindcss/postcss`

## Supabase user management

For the company-wide staff group chat and private staff messages, apply `supabase/migrations/20261103121409_staff_chat_and_notifications.sql` and `supabase/migrations/20261103124905_staff_chat_read_receipts_and_deletion.sql`. Chat is available to active company members independently of email, SMS, and WhatsApp permissions. Group messages are company-visible; private messages are limited to their sender and recipient. Senders can see private read receipts and group readers; company owners, General Managers, and Supervisors can delete group messages for everyone, private senders can delete for everyone, and private recipients can delete for themselves. Message alerts use the existing in-app notification and browser/device push delivery.

Apply all pending migrations through `supabase/migrations/202610250001_company_slugs.sql` before starting the updated app. Company slugs are used for multi-tenant URL routing (e.g., `https://recruit.kilaxtech.com/kilax-dammy-recruit/login`); slugs are auto-generated from the first word of the company name and are used for SEO-friendly, case-insensitive URL paths. SMS contact groups and group members are company scoped. For Pipeline bulk SMS and Recruitment Agent notes in Communications, apply `supabase/migrations/20261105065728_candidate_agent_sms_notes.sql`; SMSUG sends immediately to selected candidates, and only the active Recruitment Agents assigned to those candidates receive a note and notification. For Tasks access across every company role and personal to-do reminders, apply `supabase/migrations/20261102133528_enable_tasks_for_all_members.sql` after `supabase/migrations/202610040025_google_tasks.sql` and `supabase/migrations/202610040026_smsug_communications.sql`. New tasks belong to the creator and cannot be reassigned; existing tasks assigned to a member remain visible to that member. A task defaults to a reminder 10 minutes before its due time, and an unfinished task notifies only its creator in-app and through optional push notifications. The existing push-dispatch cron sends reminders once; SMS reminders are optional and require `communications.sms.send` plus a phone number on the creator's profile. In SMSUG Settings > API Settings, turn API access on and set `SMSUG_API_KEY` only in the server environment; never expose it through a `NEXT_PUBLIC_` variable. SMSUG sends immediately and charges the account balance; check Sent Messages before retrying an ambiguous send.

For the personal To-do List and staff-assigned task workflow, also apply `supabase/migrations/20261103065113_task_assignment_and_todo_workflow.sql` after the Tasks and SMSUG migrations. Tasks can be created as private personal to-dos or assigned to an active company staff member; assignments cannot be transferred after creation. Assignees and active General Managers, Supervisors, and Projects Managers in the creator's branch receive in-app/push notifications. Opening the assignment or marking its notification read acknowledges it; otherwise, after three minutes, the assignee receives a reminder and an SMSUG message when `SMSUG_API_KEY` and a valid phone on their profile are configured. While an assigned task remains incomplete, in-app/push reminders recur every ten minutes. Completion feedback goes to the creator and the original branch CC recipients.

For multi-tenant company login pages, the `companies.slug` field must be populated (auto-migrated on first migration run). Access company-specific login pages at `/{company-slug}/login` with company-branded header, logo from `companies.logo_url`, email/password login, forgot password flow, and WhatsApp contact button for the company chairman (`primary_admin_user_id`). No Google/Microsoft OAuth on company-scoped login pages.

For the shared WhatsApp inbox, set `ZERNIO_API_KEY`, `ZERNIO_WEBHOOK_SECRET`, and `SUPABASE_SERVICE_ROLE_KEY` only in the server environment; never expose them through `NEXT_PUBLIC_` variables. Apply all migrations through `202610110002_zernio_whatsapp.sql`. A company owner connects a WhatsApp Business number from Communications > WhatsApp using Zernio's hosted Embedded Signup; RecruitOS creates a Zernio profile for the company and subscribes an account-scoped webhook to `/api/communications/whatsapp/webhook`. The Zernio API key and webhook signing secret are server-only. WhatsApp read/send access is controlled by `communications.whatsapp.read` and `communications.whatsapp.send`, while only the primary company administrator can manage the connection by default. Zernio supports approved template sends for new conversations and outside the 24-hour customer-service window; company members must provide the approved template name, language, and variable values when starting a new conversation.

For the Users & Roles staff roster, Human Resource self-service, and Paychecks, apply `supabase/migrations/202610130001_company_staff.sql`, `supabase/migrations/202610130002_staff_hr_profile.sql`, `supabase/migrations/202610130003_staff_auto_enrollment_payroll.sql`, then `supabase/migrations/202610130004_payroll_adjustment_batches.sql`. Staff roster records are company-scoped and managed by the primary owner, CEO, or General Manager; only the primary owner can change the staff ID prefix and next sequence. Company accounts are automatically linked to staff records when memberships are created. Employees can update their own HR profiles and private personal documents from Human Resource. Payroll payments require finance permissions and generate a branded payslip immediately; recorded monthly benefits and deductions are included in each employee's payslip. Only one paycheck can be recorded per employee per pay month.

For unpaid leave payroll controls, apply `supabase/migrations/20261113121735_unpaid_leave_payroll_guards.sql`. Company leave types can be marked paid or unpaid. Approved unpaid leave of up to six days blocks benefit payments during the leave dates; longer approved unpaid leave creates a zero-net-pay payroll row for each affected month and blocks that month's benefits and paycheck.

For unrestricted company-owner workspace access and sequential payroll references, apply `supabase/migrations/20261113125137_chairman_full_company_access_and_payroll_references.sql`. The primary company administrator can access every workspace permission and branch in their own company. Benefit and deduction batches generate a unique, continuously increasing payment reference for each selected staff member; references continue growing beyond six digits.

For company attendance schedules, public holidays, and role-based staff attendance controls, apply `supabase/migrations/20261103103918_company_attendance_schedule_and_closures.sql` after the attendance and leave migrations. The Chairman configures weekly office hours and closure dates in Settings, views daily/weekly/monthly company attendance, and can export reports as PDF or Excel. General Managers and Supervisors have daily team attendance and can record check-in/out for staff; the Chairman cannot clock in or out. Other staff can view their own attendance. Non-Chairman users must complete their personal HR details (name, phone, date of birth, sex, local address, next-of-kin name and phone, and emergency-contact address) before accessing the workspace; other HR sections can be completed later.

For staff HR profile reminders, apply `supabase/migrations/20261103114331_staff_hr_profile_reminders.sql` after the staff HR profile migration. The required personal details are checked at initial workspace access. Ten days after completion, staff are reminded to review remaining HR sections and may defer the reminder for another ten days or confirm their review. Six weeks after confirmation, staff are asked whether their contact/address information is unchanged; if it changed, they must update and save at least one personal contact or address field before resuming workspace access.

For Finance Accounts and account-linked receipts, invoice payments, expenses, and payroll, also apply `supabase/migrations/202610130005_company_accounts_books.sql`. Company owners, CEOs, General Managers, and Finance Managers can create accounts; each new money-in or money-out transaction must select an active company account.

For Chairman-managed expense categories required when recording company expenses or submitting requisitions, apply `supabase/migrations/20261112221809_company_expense_categories.sql`. Existing expense types up to 100 characters are migrated into categories; categories can be deactivated and reactivated from Settings.

For the reusable company item catalog, multi-item expense recording, and Chairman-only agent and partner editing, apply `supabase/migrations/20261112223124_company_expense_items_and_owner_edits.sql` after the expense-category migration. Expense totals are calculated from line items and saved atomically with the account ledger; new requisition and expense items can be saved to the company catalog for reuse. Agent edits retain candidate assignments by user ID; changing an agent's email changes that user's login email immediately across company memberships.

For Finance expense requests and the Administration Officer default role, apply `supabase/migrations/20261104083230_finance_expense_requests.sql` after the company accounts and workspace notification migrations. Expense requests follow General Manager review, Finance verification, Chairman authorization, and Finance Manager cash-out from an active company account. Each review stage requires a comment, creates the corresponding company expense when paid, and sends permission-scoped in-app and browser/device push notifications.

For staff-submitted expense requests and requisition initiation, apply `supabase/migrations/20261113144515_staff_expense_request_line_manager_workflow.sql` after the staff line-manager, requisition, expense-category, and expense-request migrations. Active linked Staff submit requests with a category and item lines; their active linked line manager reviews or rejects them, with General Manager review as fallback if no active manager is linked. The Administration Officer sees approved requests in the Requisitions initiation queue, where initiation creates a read-only linked requisition showing both ER and REQ numbers and the original staff requester. Subsequent approvals and cash-out stay on the Expense Request chain, and the Administration Officer cannot access the Expense Requests page.

For Finance staff to view candidates and inquiries without editing candidates or changing pipeline stages, apply `supabase/migrations/20261102104942_finance_candidate_read_role_permission_persistence.sql`. The migration grants `candidates.view` to standard Finance roles while leaving `candidates.edit` unchanged. Role permission updates are saved atomically, and active workspaces refresh updated permissions.

For staff Agents & Partners access, apply `supabase/migrations/20261102130106_align_agent_and_supplier_access.sql`, `supabase/migrations/20261102131202_restrict_agent_finance_to_recruitment_agents.sql`, and `supabase/migrations/20261102131944_remove_agent_finance_from_non_agent_roles.sql`. The staff Agents roster requires both `users.view` and `candidates.view`; adding agents also requires `users.edit`. Agent Invoices & Receipts is restricted to the protected Recruitment Agent role, regardless of permission grants on other roles. Partner creation is shown only to roles with `suppliers.create`, and current Chairman roles receive the partner defaults. The partner UI retains the existing supplier table, API route, and permission codes for data compatibility.

For read-only Finance access to medical appointments, apply `supabase/migrations/20261102111623_finance_read_only_medical_appointments.sql`. Users with `finance.view` can view appointments; booking requires `candidates.create` or `medical.update`, so `finance.create` alone does not grant booking access.

For staff pay arrangements, configured base salaries, and recurring weekly transport benefits, apply `supabase/migrations/202610140002_staff_payroll_compensation.sql` after the company accounts migration, then apply `supabase/migrations/20261115231920_staff_transport_account_modes.sql` after the attendance schedule and closures migration. In Users & Roles, a Chairman can choose a fixed active account for the allowance or allow Finance to select an eligible active account when paying it. The monthly transport benefit is calculated from the selected pay month's scheduled working days, excluding company closure dates, and is included in the payslip and payroll ledger.

For separate candidate and contractor project charges and automatic project books, apply `supabase/migrations/202610140001_project_contractor_candidate_charges.sql` after the company accounts migration. Project candidate service charges create candidate visa invoices; contractor service charges accrue once per candidate visa and appear in Contractor Finance. Candidate deposits and candidate invoice payments are associated with the assigned project's book. Finance > Invoices can be filtered by employer or partner. Payments & Deposits shows project attribution and supports project-filtered Excel and PDF exports; candidate deposits use the stored project association with the candidate's visa invoice as a fallback for older receipts.

For project creation delegation, Projects Manager routing, candidate workflow access, and Chairman-only contractor edits, apply `supabase/migrations/20261113095501_projects_manager_assignments_and_contractor_edits.sql`, `supabase/migrations/20261113103912_projects_manager_candidate_workflow_permissions.sql`, and `supabase/migrations/20261113112604_candidate_medical_documents_follow_document_permissions.sql` after the company staff migrations. The Chairman can grant the `projects.create` permission to a role in Users & Roles; members of that role can create projects. The Chairman selects an active company staff member with the Projects Manager role when creating or editing a project; the field searches staff by name and position. If no eligible staff member exists, the project remains unassigned until one is added to the staff roster and assigned that role. The Projects Manager can view and edit candidates, update stages, submit candidates to projects, view and create inquiries, and manage candidate documents. The assigned Projects Manager can assign the project to an active staff member, and the Chairman can assign any project to an active company staff member. The Chairman can edit existing contractor details using the contractor registration form.

For Chairman-only deletion of a staff roster record and its company membership, apply `supabase/migrations/20261113115818_chairman_staff_record_deletion.sql`. Auth accounts with memberships in other companies are retained; staff with payroll history or active direct reports cannot be deleted and should be deactivated or reassigned instead. Membership-linked records such as attendance and staff chat are removed with the membership.

For company-managed candidate registration sources and unique passport numbers, apply `supabase/migrations/20261101083540_candidate_registration_sources_and_passport_uniqueness.sql`. Candidate source options are company scoped; the Chairman can add sources and grant `candidates.sources.manage` to other roles from Users & Roles. Passport numbers are unique across the database regardless of letter case or surrounding spaces; the migration rejects existing duplicates until they are resolved. Candidate finance totals and transactions are loaded from live records and are visible only to the Chairman/primary administrator and finance roles with `finance.view`.

For company-prefixed inquiry and candidate file numbers, apply `supabase/migrations/20261117072743_candidate_inquiry_and_file_number_sequences.sql` after the candidate inquiry and candidate tables exist. Inquiry numbers are assigned once and retained when an inquiry is registered; staff and Recruitment Agent entries use separate `IQ` and `IQA` series. Registration file numbers use `FLN`, are assigned automatically when the completed registration is saved, and cannot be manually changed.

For default company candidate sources and source-specific partner referrals, apply `supabase/migrations/20261117084300_candidate_source_defaults_and_referral_partners.sql` after the candidate source options table exists. Settings > Candidate Sources includes TikTok, Referred by Candidate, Recruitment Agent, and Partner by default, plus the legacy inquiry sources used when converting older inquiries. Partner referrals require selecting an active partner from the company Partners list; Recruitment Agent referrals require selecting an active company Recruitment Agent, who is also assigned to the candidate.

For live, permission-checked passport-number availability validation during registration, apply `supabase/migrations/20261101220355_candidate_passport_validation.sql` after the candidate source and passport uniqueness migration. The lookup reveals only whether a passport is registered and the registering staff member's display name, and only to active users permitted to register candidates.

For Recruitment Agent candidate isolation, apply `supabase/migrations/20261102091421_enforce_recruitment_agent_candidate_scope.sql` after `supabase/migrations/20261030064119_recruitment_agent_access_controls.sql`. It enforces assigned-candidate visibility in database policies even if role settings are changed; the dashboard metrics follow that same candidate scope.

For candidate processing history and passport withdrawal or transfer follow-ups, apply `supabase/migrations/20261102055732_candidate_passport_workflow.sql` after the passport validation migration. Passport status changes are restricted to the primary administrator/Chairman, General Manager, or Supervisor; withdrawn or transferred passports can return to Available and the candidate to Registration after 30 days. Active project handlers and submitters receive internal communications, alerts, and follow-up tasks; contractor cancellation emails are instructions for staff and are not sent automatically.

For independent candidate workflow actions, apply `supabase/migrations/20261102141655_candidate_stage_and_project_submission_permissions.sql` after the candidate passport workflow migration. It adds `candidates.stage` and `candidates.project_submit`, preserves current access by granting them wherever `candidates.edit` is already assigned, and enforces the grants in the UI, API, candidate RLS, and project-submission RPC. New role edits can then configure stage updates and project submissions separately from candidate profile edits.

For Reports & Analytics access, apply `supabase/migrations/20261101105601_reports_analytics_view_permission.sql`. `reports.view` is granted by default to Chairman/CEO and primary-administrator roles; users with role-management permission can grant it to another role from Users & Roles, then assign that role to the intended user. Report sections continue to return only data allowed by the user's other module permissions.

For Gmail OAuth, set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` only in the server environment and register `/api/communications/mail/callback?provider=gmail` using the `NEXT_PUBLIC_SITE_URL` origin. When a workspace user signs in with a `@gmail.com` address, Communications preselects that address and requires one-time Google consent before accessing its mailbox. Connected accounts expose Inbox, Outbox/Sent, Spam, and Drafts. Existing Outlook OAuth connections remain supported; Microsoft OAuth credentials are only needed if using its legacy OAuth flow. Users with other email addresses can add custom mailboxes from Communications with their IMAP/SMTP hosts, ports, TLS settings, username, and password or app password. Set `MAIL_TOKEN_ENCRYPTION_KEY` to 64 hexadecimal characters generated from 32 random bytes; back it up securely because changing it invalidates stored mailbox tokens and IMAP/SMTP credentials. Mail tokens and server credentials are encrypted at rest. Mailbox sync runs while a signed-in user opens or refreshes Communications; background push delivery is not configured. Company-owner self-registration requires `SUPABASE_SERVICE_ROLE_KEY` on the server and provisions the registrant as Chairman after email verification. Welcome emails are sent to both the registrant and company contact using server-only `SYSTEM_SMTP_HOST`, `SYSTEM_SMTP_PORT`, `SYSTEM_SMTP_USER`, `SYSTEM_SMTP_PASS`, and optional `SYSTEM_SMTP_FROM`; the uploaded PNG/JPEG company logo is embedded in the welcome email. The company user invitation and role-management API also requires this key; optional task SMS delivery uses it to securely deliver to the assigned staff member. Keep these secrets private and never expose them through a `NEXT_PUBLIC_` variable.

For AI Assistant features, set `OPENAI_API_KEY` only in the server environment; never expose it through a `NEXT_PUBLIC_` variable. `OPENAI_MODEL` is optional and defaults to `gpt-4o-mini`. Apply `supabase/migrations/202610120001_ai_usage.sql` to enable company-scoped token totals. Candidate data used to generate a document is sent to OpenAI for processing. Generated PDF drafts are saved in the candidate's document folder and appear in the candidate attachments drawer and Documents Management; inquiry chat is kept only in the open session. Token usage totals are stored by company. Users with `candidates.view` and the required document upload permissions can generate CV drafts; medical forms are blank administrative drafts and must be completed and verified by a licensed clinician. Academic profiles are clearly unofficial summaries based only on recorded candidate data and must never imitate examination certificates or invent results.

After applying the candidate document storage migrations, run `npm run storage:provision-candidate-folders` once to create both InterServer folders for existing candidates and move their attachments into the named candidate folders. New candidate folders are created during registration.

After applying the company root folder access migration, run `npm run storage:organize-company-folders` once to ensure each company root has `users`, `finance`, `candidates`, and `drive` directories, move primary-user vault files into `drive`, and move existing Finance Drive files into `finance`.

Set `NEXT_PUBLIC_SITE_URL` to the canonical app origin used in invitation emails and company signup verification, and add that origin to the Supabase Auth redirect URL allow list. It defaults to the current request origin when unset.

Set Supabase Auth's email OTP expiry to 3600 seconds. Invitation acceptance records expire after one hour, and the raw Supabase confirmation token lifetime is controlled by this project-level setting.

Configure Supabase Auth's **Invite user** email template from `supabase/templates/invite.md` so invitation messages include the inviting company and assigned role.

## Styling

Use Tailwind utility classes directly in JSX and put global CSS or Tailwind v4 theme customization in `src/index.css`. The root layout imports this file; `postcss.config.mjs` enables Tailwind.

Keep CSS `@import` statements first, then add any `@font-face` rules and font-family defaults in `src/index.css`.
