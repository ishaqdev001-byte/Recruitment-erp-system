# Recruitment ERP

Next.js App Router application using React 19, TypeScript, and Tailwind CSS v4.

For the standalone Recruitment Agent roster and account linking, apply `supabase/migrations/20261124160000_company_recruitment_agent_roster.sql`, `supabase/migrations/20261125103252_company_recruitment_agent_codes.sql`, and `supabase/migrations/20261125105321_company_recruitment_agent_time_codes.sql`. Users with `agents.manage` can create accountless agents or provision a login directly with an email, company-scoped username, and initial password; no invitation email is sent. Each agent receives a company-unique five-character code made from up to three name initials and a suffix derived from the agent's creation time; collisions are resolved while preserving the timestamp-based starting point. Existing codes are regenerated from each agent's saved creation time. Agents sign in on the company login page with their username and password and must change the initial password at first sign-in. Accountless agents can be linked later by setting an email and initial password. Only the Chairman can reset linked agent passwords. The permission is enabled for Chairman roles and can be assigned to other roles in Users & Roles. Accountless agents receive Pipeline bulk-SMS updates at their saved phone number; SMSUG configuration and charges apply. This standalone roster replaces the older Users & Roles note below that describes the Agents page as listing only company users.

## Development

Run `pnpm dev` to start the development server on port `37737`, `pnpm build` to create a production build, and `pnpm start` to serve it on the same port. Deployments using the start script must expose/forward TCP port `37737`.

## Recruit Admin

The standalone platform control panel is in the sibling directory `D:\PROJECTS\recruit-admin-panel`, separate from this ERP app. Configure its `.env.local` with the server-only `RECRUIT_ADMIN_EMAILS` allowlist, the ERP Supabase project credentials, and the same InterServer storage settings. Apply `supabase/migrations/20261127130937_recruit_admin_company_storage.sql` before using the panel or enforcing storage allocations. Companies remain unlimited until a limit is assigned; refresh measured storage before setting a limit. ERP uploads are checked against allocations, and deletes release accounted bytes.

For browser and closed-browser push alerts, apply `supabase/migrations/20261031123905_browser_push_notifications.sql`, `supabase/migrations/20261031131429_notification_push_cron_scheduler.sql`, and `supabase/migrations/20261031140816_workspace_notification_events.sql`. The last migration adds permission-scoped event notifications for candidates, tasks, approvals, finance, HR, medical examinations, and inbound WhatsApp messages; legacy leave, requisition, and reminder notifications remain supported. Set `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, and `NOTIFICATION_DISPATCH_SECRET` only in the app server environment. In Supabase Vault, create secrets named `notification_app_base_url` (the HTTPS app origin) and `notification_dispatch_secret` (the same value as the app's `NOTIFICATION_DISPATCH_SECRET`). Supabase Cron then calls `/api/notifications/push/dispatch` every minute. Users opt in from the notification center; push subscriptions are scoped to the signed-in user and alerts are permission-filtered.

For staff self-service profile names, phone numbers, and profile photos, apply `supabase/migrations/20261104093919_user_profile_photos.sql`. The migration adds `profiles.avatar_url` and a private Storage bucket; profile photos are served through the authenticated `/api/workspace/my-profile` route and are not public URLs.

For the company position catalog, apply `supabase/migrations/20261119124329_company_staff_positions.sql`. Existing staff position names are imported into Settings > Positions; the Chairman and users granted `staff.positions.manage` can add, rename, deactivate, reactivate, or delete positions. New and invited staff select an active company position. The permission can be assigned when creating or editing a role. Deleting a position preserves the existing staff position label as history.

For staff line-manager assignments and employee employment summaries, apply `supabase/migrations/20261113045438_staff_line_managers.sql`. Staff invitations let administrators choose Staff or Member; email invitations require the invitee's phone number. When inviting an existing active, unlinked staff member, search by name and select the roster record to autofill its saved details and link the account instead of creating a duplicate. New Staff invitations create a linked roster record with branch, line manager, and pay details. Users with `users.edit` can unlink an active Staff account after reassigning its direct reports; this disables that company's membership, marks the staff record inactive, and preserves both records. The Chairman or another authorized user can relink it by entering a new email; the same login account keeps its company role and receives a 30-minute invitation link requiring a new password. Company access remains disabled until the invite is accepted. The login email is account-wide and changes for any other company memberships, while access is disabled only for the current company. Revoking a pending invitation disables company access but keeps the user visible in Users & Roles and retains the Staff-page record; use Resend invite to invite the account again. Deleting a company user unlinks but does not delete their staff record. The Agents page lists company users assigned the Recruitment Agent role; invitations are managed from Users & Roles. The Chairman can edit the Main Branch and change a user's Staff/Member type from Users & Roles; changing Staff to Member retains the staff history and marks its roster record inactive. The Chairman, General Manager, and Supervisor can filter visible users by branch. Employees can view their own position, line manager, branch, monthly salary, and weekly transport allowance in Human Resource.

For Pipeline bulk SMS and Recruitment Agent notes in Communications, apply `supabase/migrations/20261105065728_candidate_agent_sms_notes.sql`; SMSUG sends immediately to selected candidates, and only the active Recruitment Agents assigned to those candidates receive a note and notification. New tasks belong to the creator and cannot be reassigned; existing tasks assigned to a member remain visible to that member. A task defaults to a reminder 10 minutes before its due time, and an unfinished task notifies only its creator in-app and through optional push notifications. The existing push-dispatch cron sends reminders once; SMS reminders are optional and require `communications.sms.send` plus a phone number on the creator's profile. In SMSUG Settings > API Settings, turn API access on and set `SMSUG_API_KEY` only in the server environment; never expose it through a `NEXT_PUBLIC_` variable. SMSUG sends immediately and charges the account balance; check Sent Messages before retrying an ambiguous send.

For the personal To-do List and staff-assigned task workflow, also apply `supabase/migrations/20261103065113_task_assignment_and_todo_workflow.sql` after the Tasks and SMSUG migrations. Assignees and active General Managers, Supervisors, and Project Handlers in the creator's branch receive in-app/push notifications. Opening the assignment or marking its notification read acknowledges it; otherwise, after three minutes, the assignee receives a reminder and an SMSUG message when `SMSUG_API_KEY` and a valid phone on their profile are configured. While an assigned task remains incomplete, in-app/push reminders recur every ten minutes. Completion feedback goes to the creator and the original branch CC recipients.
